## Navigation, scope and status rules checked against source

- Listing has separate `EA_ACCESS`, `RESPONDENT_ACCESS`, and `APPROVER_ACCESS` access views. Opening a row reads `getSecurityUser_roles` for `ETHICS` with that setup ID, then `getDynamicFormsApplicationSetup`. Administration opens General Overview if that page is readable; other views enter Responses. Detail initialization redirects to Responses when Overview is unavailable. Direct refresh reloads object roles. See `ViewEthicsApplicationButtonActionChain.js`, `ethics-detail-page.js`, and `ethics-detail-page-chains/initializeChain.js`.
- The detail tabs are General Overview, Responses, Attachments, Approvals, and History. Each requires the matching object page read role. General Overview is present only for a draft or the administration access view. The global editable status list contains only `DRFT` in the checked source. See `ethics-detail-page.js` and `ethics-detail-page.html`.
- The setup payload's `stakeholders` rows contain `id` (response/document object ID), `p_id` (person ID), response status and organization. The signed-in `person_id` chooses the initial stakeholder; administration falls back to the first. Responses may use the mentioned person's `object-id` deep link only if that `p_id` exists in the setup. See the `fetchEthicalSetupDataChain.js` and Attachments `fetchEthicsDataChain.js`.
- Responses' shared dynamic form uses `p_id` and `p_obj_id` = setup ID, `p_ref_module`/object type = `ETHICS`, `p_tag_type=ETHICS_TYPE`, and `p_tag_value` = form type. Answers use stakeholder `id` as `P_REF_OBJ_ID`, `P_REF_MODULE=ETHICS`, and selected `p_id` as `P_PERSON_ID`; saving uses stakeholder `id` as `P_OBJECT_ID`. Respondent editing requires respondent access, own stakeholder, draft response, and an unlocked/unfinalized page. See `ethics-responses-start-page.html` and `fragments/dynamic-form/chains/loadDynForm.js`/`submitDynForm.js`.
- Attachments mount only after a stakeholder ID exists, use object type `ETHICS`, object/reference ID and storage number = selected stakeholder ID, and permit changes only with page edit access and editable response status. Folder tree is enabled; confidential files are disabled; links require the bundle's `header-labels.attachment-links-header` visibility. See `ethics-attachments-start-page.html`.
- History status rows use the **first** stakeholder ID, while approval history's document number follows the selected stakeholder. Add Status and Abandon each require a separate edit role and visible resource key. See `ethics-history-start-page.html`.
- Approvals use setup ID as workflow object ID, selected stakeholder ID as `objRefId` and `docNum`, and `ETHICS` as type. Individual attachments use the stakeholder folder; collaborative attachments use setup ID. Stage/approver management has separate object role keys. Approver action mode requires `APPROVER_ACCESS`; respondent withdrawal requires `AIA`, the respondent/creator rule, auto-submit metadata, and visible Withdraw resource. See `ethics-approvals-start-page.html`.
- Overview submission requires header validation, at least one stakeholder, at least one reviewer, form metadata/sections, and an explicit `SUBMIT` setup payload. Draft uses `SAVE`. Linked references are flat objects, one per linked ID. Setup edit/version, delete, clone, print, finalize and lock controls have their own role, status and resource gates in the detail shell; do not treat a tab's edit role as permission for these actions. See `GeneralOverviewPageTemplateSpPrimaryActionChain.js` and `ethics-detail-page.html`.
