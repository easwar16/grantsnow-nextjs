# Proposal Budget staff and student entry — 2026-11-05

The VBCS Staff costing page starts with a searchable person picker. Student Cost and Pooled Technician Cost start with personal detail fields instead. All three load the Proposal Staff Cost Additional Info dynamic form and create a costing header before showing generated cost lines. This implementation uses a dedicated shared StaffEntry page for those three modes; Non Staff retains the existing cost editor.

The current Next.js page reads the same global Org Unit lookup as VBCS. Oracle sometimes returns uppercase column names, so the entry service normalizes them through the established org-unit parser before building picker options. The staff search now opens eligible suggestions on focus, matching VBCS. It retains the backend's stage-specific costing eligibility flags and only falls back to the general flag when neither stage flag is present. Selecting a person fetches the costing master-view details and fills the personal fields. The Student Cost layout keeps the VBCS three-row action toolbar, compact header, inline required marks, and Override Inflation on its own row.

The dedicated VBCS preview and live Next.js page were compared at proposal 10205. The Next.js Org Unit picker showed Indian Institute of Technology, Secondary Role, University of Essex, and Grants Now dev, among other entries, after the fix. The staff picker showed To Be Decided immediately on focus, and selecting it populated Full Name, Employee number, Org Unit, Faculty / School, Project role, Costing HDR section and HR FTE. The local server was restarted on `127.0.0.1:3000` because Turbopack's hot module graph retained the old `costingScope` export in the new route bundle.

The generated cost lines are currently shown as a summary after header insertion. Editing and saving individual generated lines, plus exact VBCS salary/indirect field handling, remain to be implemented. No agent-initiated live Oracle write was performed while verifying this entry page.

The dedicated VBCS preview showed that the staff search remains available after choosing a person. The `InputSearchValueActionChain` clears the search and replaces the person details and costing header fields when a different person is picked; it skips reloading the same person. The Next.js picker now keeps the search visible and clears prior generated lines and dynamic form answers on a different selection. The VBCS page renders Probation end date with `oj-input-date` and HR FTE read-only, so Next.js now uses the shared date control and a read-only HR FTE field.

There is a source/preview discrepancy for First Increment: the checked-out VBCS page's `returnFirstIncrement()` returns JAN through DEC, but the separate live VBCS preview's open `cbFirstIncrement` offered `JAN-2025` through at least `JAN-2027`, and selecting `JAN-2025` set that exact value. Next.js follows the live preview for employee number zero with searchable month-year choices from 2025 onward. The live picker endpoint did not expose its upper bound through the checked-out source, so the Next.js list currently extends through 2035. Employee number nonzero retains the VBCS text field. A legacy month-only value is shown blank in the month-year picker until a matching value is chosen, as in the VBCS preview. This upper bound and the underlying preview data source still need direct confirmation before declaring exact LOV parity.

The VBCS `AddNewCostActionChain` explicitly resets its Staff page variables, costing summary and dynamic-form answers and reruns lookups and proposal data when Add New Staff Cost is clicked on the same page. Next.js now clears the current staff draft (including person, generated lines, dates, selections, answers and errors) and refreshes the server-loaded options on that click. In-flight person or line responses are ignored after reset. The same reset applies to clicking the current Student or Pool-Tech action.

VBCS's Staff Availability icon appears beside the staff search and is enabled only after a person is selected. `OpenTimeLineActionChain` calls `getReportsGetStaffTimeReport` with that person's employee number and the proposal start/end dates. It opens a timeline dialog if rows are returned, otherwise shows `No Relevant Staff Data Found`; request failure shows `Error Occured` in that VBCS chain. Next.js now uses the same read-only Oracle operation and displays the proposal dates and returned proposal/FTE date bars in a dialog. The fixture browser journey verifies the button, timeline contents, close action and same-page new-cost reset. A live DEV read at proposal 10205 returned staff assignments through 2031 and opened the dialog with those rows. No agent-initiated live Oracle write was performed.
