# Proposal creation through shared Summary

- **Date / author / agent:** 2026-11-05 / easwar / Codex
- **Branch / base commit:** `codex/proposals-azure-integration-20261030` on the existing worktree; unrelated uncommitted changes preserved.
- **Why:** VBCS creation enters the Proposal Summary flow without a `proposal_id`. Next.js had a separate, incomplete creation form.
- **What changed:** The new route now renders the shared `Summary` component in creation mode. It reuses its PI picker, Proposal Details fields, funder and deadline editors, configured attributes, opportunity fields, research partner and subproposal editors, and dynamic form. The duplicate route-local form and CSS were removed. Creation loads `getSecurityUser_roles` with `p_obj_type` and no `p_obj_id` before rendering, then requires Summary read access. The create payload now carries configured attributes and partner rows. Dynamic answers save after Oracle returns the new proposal ID, only when changed. Both the top and bottom actions submit the same form. The toolbar, PI block, field spacing, attribute labels, and table heights were aligned with the provided VBCS screenshots. Client validation follows the VBCS sponsor/partner checks before the rest of the Summary fields: it scrolls to and focuses the first invalid control and renders the specific message beside it. Dynamic and configured attribute errors also focus their marked field on creation without a generic toast. Success uses the type's RB `success-msg.created` as a transient toast; backend errors retain `error_code : error_description` and `preventive_action` in a persistent toast.
- **Shared pieces used or extended:** `Summary`, `ProposalEditForm`, `ProposalPiEditor`, `ProposalSponsorsEditor`, `ProposalDeadlinesEditor`, `ObjectAttributes`, `DynamicForm`, and the existing create API.
- **Replaces / overrides:** Replaces the separate creation form from `2026-11-02-easwar-proposal-create-entry.md`; AOI prefill remains in the route.
- **Rules touched:** Uses shared UI components and stable ids. The shared role API now permits the legacy no-ID request for creation; the create service fails closed when Summary read is absent. This changes the framework role helper for a verified VBCS creation behavior.
- **Checks:** Typecheck, lint (one existing TanStack Virtual warning), 904 unit/integration tests, isolated production build, four focused fixture browser journeys, and the full browser suite (41 passed, 2 skipped) passed after the validation change. The focused browser test verifies that missing primary sponsor and title errors focus their controls and display the field message without a generic popup, and that backend error attributes and RB success messages remain intact. The live preview showed the bottom action and an earlier user-triggered save created P_6751 / ID 10203 with subproposal SP_908 / ID 10204; the follow-up unchanged dynamic form save had failed and was fixed. No agent-initiated live Oracle write was run.
- **Open:** Visual parity needs a final live DEV comparison after the user refreshes the preview. The configured dynamic forms depend on DEV resource and role data.
