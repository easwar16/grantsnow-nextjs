# Ethics record host, History and Documents increment

- **Date / author / agent:** 2026-11-05 / easwar / Codex
- **Branch / base commit:** `codex/proposals-azure-integration-20261030` on `118d553`
- **Why:** The existing Ethics record required `ethics-general-overview` read permission for every access view. VBCS `ethics-detail-page.js#getTabs` filters each page by its object role and its direct-entry chain reloads those roles. The VBCS History and Documents fragments use stakeholder IDs rather than the setup ID.
- **What changed:** The record resolves a permitted access view, reloads object roles on direct entry, exposes only readable tabs, and renders via `RecordFrame`. History uses the shared object-history host with its first stakeholder ID. Documents use the shared attachments host with the stakeholder ID and a draft/edit role gate. The shared comments/audit panel host is registered for Ethics pages. Explicit failures now reach a specific error state.
- **Shared pieces used or extended:** `RecordFrame`, `ObjectHistory`, `AttachmentsTab`, shared object panel/history/attachment host registries, resource labels and gates.
- **Replaces / overrides:** Extends the limited record overview in `2026-11-02-easwar-ethics-entry.md`; it removes its unconditional Overview gate. Refines the record portion only, leaving listing and creation intact.
- **Rules touched:** Object-scoped access and organization checks remain server-side; History and Documents reuse shared hosts. Attachment confidentiality is explicitly off for Ethics as in its VBCS fragment. No Oracle operation was added and no live write was made.
- **Checks:** `npx tsc --noEmit --incremental false`, lint (one pre-existing TanStack warning), 904 unit/integration tests, isolated production build, five focused fixture Ethics Chromium journeys and the full fixture browser suite (44 passed, 2 skipped) passed. A first focused browser run failed because the test expected the full comment text in a deliberately truncated table cell; the corrected test passed. Live DEV Ethics reads and writes were not verified.
- **Open:** This is **not a complete Ethics migration**. The dynamic form, participant selection, reviewer/stakeholder changes, references, versions, locks, clone/delete, submit/response and approval actions, and full record labels/visual parity remain. History and Documents currently use the first stakeholder because the participant selector is not built. Their selected-participant behavior and object response shape need real DEV read verification. The fixture test covers only the first stakeholder. Live mutations require an authorized DEV test record and side-effect policy.
